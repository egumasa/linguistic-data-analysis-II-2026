A · What NLP tasks are there

What is annotation?

Annotation = adding interpretive labels to language.

  • POS — noun / verb / adjective…
  • Word sense — which meaning of bank?
  • Stance / engagement — is the writer hedging, endorsing?
  • Discourse moves — what is this sentence doing in the argument?
  • Error tags, CEFR level, …

The common shape: a unit of language → a label. That’s the whole game.

Annotation is the foundation of corpus linguistics

Raw text is only searchable by word form.

Annotation makes it searchable and analyzable at the level of meaning and function — that’s what turns a pile of text into a corpus you can ask questions of.

Annotation is the fuel of NLP

Classic NLP systems are supervised: they learn from human-annotated gold data.

  • Someone labels thousands of examples → the system learns the pattern.
  • No annotation, no model.

So NLP has always depended on annotation. Today we look at how that annotation is done well — and how we evaluate it.

Classic tasks, in linguistics

Via Eguchi & Kyle (2024) — each task = input → output over a unit of analysis, doing one of identify · extract · categorize:

  • POS tagging & dependency parsing — label every token.
  • NER — find and type spans (names, places…).
  • Span categorization — their epistemic-stance / Engagement Analyzer example.
  • Text classification — one label for a whole text.

Same three verbs, different unit — that’s the whole taxonomy.

Organize by unit + output

  • Token-level sequence labelling — POS, NER (one label per token).
  • Span categorization — stance spans (label a stretch of text).
  • Unit categorization → one label per unit — a sentence or a whole text.

The last row is the one that yields clean, evaluable gold data. That’s where the course lives.

Narrow the course focus — and why

We do sentence categorization and text categorization:

  • one label per unit → clean gold, a confusion matrix, P / R / F1;
  • the canonical {id, text, label} schema you met in S3.

Span / sequence tasks carry boundary + partial-match problems — too heavy for 5 days.

Tip

The evaluation you can teach in a week determines the tasks you can target.

Optional challenge path — error annotation

The AutoErrorAnalyzer track has two routes:

  • Default — sentence-level: one label per unit; rides the taught pipeline like every other track.
  • Stretch — locate-a-span-then-categorize: the real error-annotation task. Breaks one-label-per-unit; needs span matching + partial-match scoring.

Offered as an instructor-supported stretch, not an excluded case — a coding-guidelines + span-scoring spec is provided for teams who take it.

B · How NLP evaluates a system — and how it transfers to LLMs

The NLP evaluation workflow

Eguchi & Kyle (2024) walk the full loop:

build a gold standard → a system produces predictions → score predictions against gold.

We borrow the evaluation half — not the training half.

Model → prompted LLM

  • Classic NLP trains a supervised model on gold (context, not our method).
  • This course replaces the model with a prompted LLM…
  • …but evaluates it the same way.

That transfer is the whole reason this workflow matters here.

What “evaluation” means

  • P / R / F1, and macro-F1 across classes.
  • Confusion matrix — where the errors actually go.
  • Cohen’s κ — agreement corrected for chance.
  • Train / validation / test — the held-out logic (seed now; applied when we tune prompts in S7–S8).

Reading a 2×2 confusion matrix

Rows = gold, columns = prediction:

Pred + Pred −
Gold + TP FN
Gold − FP TN
  • Precision = TP / (TP + FP) — of what it flagged, how much was right?
  • Recall = TP / (TP + FN) — of what was actually positive, how much did it catch?
  • F1 = harmonic mean of the two.

Note

κ asks the harder question: how much do two labellers agree beyond what chance alone would give?

C · Workflow — annotation procedure & evaluation

Design the annotation scheme

  • Adapt or design an annotation scheme + coding guidelines.
  • Operationalize the category: turn a fuzzy construct into a decidable rule a second coder can follow.

If two trained coders can’t agree on it, a model can’t be trusted on it either.

Annotate blind → agreement → gold

  1. Two coders annotate the same items blind.
  2. Measure inter-annotator agreement — percent + κ.
  3. Adjudicate disagreements → a gold standard.

Tip

You’ll run exactly this in S5.

Evaluate a model against gold

Same metrics, two different comparisons:

  • annotator vs. annotator → inter-annotator agreement (IAA)
  • gold vs. model → model evaluation
