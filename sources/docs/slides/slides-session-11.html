The pipeline

One diagram

                                                              │
                            prompt ─────────────┐             │
                                                ▼             ▼

                                                              │
                                                    save_predictions
                                                              │
                                                              ▼

                                         ▼                    ▼

                                         │                    │
                                         └──────▶ export ◀─────┘

Read it as data shapes

Arrow What flows Shape
pool → sampled ~40 items, balanced [{id, text, label}]
sampled → sheet one row per item, labels blanked a Google Sheet
sheet → gold your adjudicated decisions [{id, text, label}]
gold + prompt → predictions one label per item ["B1", "A2", …]
predictions → frozen file the same list, on disk .json
gold + frozen → metrics P/R/F1, κ, matrix numbers you report

Everything after the frozen file reads the file, not the model.

PLAN.md

The 作戦シート, finally given a file

You have been building this plan since S3 — track, scheme, gold source, prompting strategy. Today it becomes one page in your repo.

It is not graded. It is a gate: no group calls the model until it is signed.

Two minutes of writing catches the failures that otherwise cost an hour after you have spent quota:

  • label set says Move 1/2/3, gold file says 1a/1b, prompt says “move one” → no error, just a confusing F1
  • labels ordered but not alphabetical → weighted κ computed over High < Low < Mid
  • nobody agreed who codes which column → one annotator, no κ

The six lines

# PLAN — <group>, track <track>
Members: …

1. Unit of analysis: (sentence / whole text) — and why
2. Label set: … (exactly the strings in your gold file)
3. Are the labels ORDERED? In what order?
4. Gold: pool file · N_PER_CLASS · SEED · expected total
5. QC: who is CoderA, who is CoderB, who adjudicates
6. Prompt plan: baseline, then the ONE change you predict
   will help — and why

Tip

Question 3 exists to catch the ordinal-κ trap. Question 6 asks you to predict before you test — which is the whole method in one line.

And the table

# Step Consumes Produces
1 sample POOL_PATH, N_PER_CLASS, SEED pool, sampled, LABELS
2 QC / adjudicate sampled, LABELS, the sheet gold
3 baseline PROMPT, gold pred0, f1_by_round
4 iterate + freeze PROMPT, pool, gold pred_final (a file)
5 error analysis gold, pred_final the errors table
6 export all of the above outputs/…_report.md
