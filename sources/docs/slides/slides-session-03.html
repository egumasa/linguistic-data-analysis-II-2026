1 · From a document to sentences

The problem

Your data arrives as paragraphs. But the unit we work with is the sentence. So we need to segment a paragraph into its sentences.

The obvious idea: cut on every full stop. To do that we call a method on the string — some_text.split(".") — using a dot (.) to run a built-in action on that value.

Why this matters

The naive rule works on simple text but fails on common cases: abbreviations and decimals contain dots that are not sentence ends.

Incorrect boundaries produce incorrect data in every later step, so it is worth seeing the naive rule fail before we use a better tool.

🧪 Let’s try — naive split

paragraph = ("Dr. Smith reviewed the data. The results were clear, "
             "e.g. accuracy rose. Scores went from 3.14 to 9.")

naive = paragraph.split(".")     # cut the string at every "."
print("pieces:", len(naive))     # how many pieces did that give us?
for piece in naive:              # look at each piece in turn
    print(repr(piece))           # repr() shows the quotes and spaces exactly

Look at the output: "Dr" (from Dr.), "e" and "g" (from e.g.), "3" and "14" (from 3.14) are all split in the wrong places. Sentence boundaries are not just full stops.

2 · Segmentation with a model

Use an existing library

Instead of our own rule, we import a library built for this task, spaCy:

### Step 1: build a sentence splitter that knows more than "cut at every dot" ###
import spacy                       # the NLP toolbox
nlp = spacy.blank("en")            # a minimal English pipeline
nlp.add_pipe("sentencizer")        # add the rule-based splitter — no download
  • import spacy loads the library.
  • The sentencizer treats abbreviations and decimals correctly, not as sentence ends.

Why this matters

Important

On Day 2, the sentence is the unit you annotate by hand and the unit you feed the LLM. Bad boundaries → bad gold data → misleading scores.

Correct segmentation is required for a correct gold standard: every label is attached to one segment.

This is your unit of analysis — the thing you attach one label to. Sometimes it’s the sentence (segment first, like here); sometimes it’s the whole text (an essay gets one rating). Session 4 formalizes this as sentence categorization vs text categorization.

🧪 Let’s try — the sentencizer

### Step 2: run it on the paragraph and look at what came out ###
doc = nlp(paragraph)               # spaCy reads the text
sentences = list(doc.sents)        # spaCy's sentence objects, as a list
for s in sentences:
    print(repr(s.text))

Compare to the naive split: Dr. Smith, e.g., and 3.14 stay intact. You now have a real list of sentences — exactly what the next section loops over.

🧪 Step 3 — the loop

for sentence in examples:              # repeat everything below for each sentence
    prompt = f"What CEFR level (A1-C2) is this sentence? Answer with just the level. {sentence}"
    reply = ai.generate_text(prompt).strip()   # .strip() removes stray blank space
    if reply == "":                    # the model sometimes says nothing at all
        print(sentence, "→ (no answer)")
    else:                              # normal case: it answered
        print(sentence, "→", reply)

The f-string sits inside the loop, so the braces are filled in again for every sentence.

🧪 Step 4 — loop over records

Every dataset this week is a list of dicts. Each item is a record, so you reach in by key:

items = [{"id": 1, "text": "The cat sat on the mat.", "label": "A1"},
         {"id": 2, "text": "More research is needed.", "label": "B1"},
         {"id": 3, "text": "Nevertheless, the findings were inconclusive.",
          "label": "C1"}]

for item in items:                 # item is one record — a dict
    print(item["id"], "|", item["label"], "|", item["text"])

🧪 Step 5 — build a list with .append

Often you don’t want to print each item — you want to keep something from it:

labels = []                        # start empty; the loop fills it
for item in items:
    labels.append(item["label"])   # add this item's label to the end

print(labels)                      # ['A1', 'B1', 'C1']

The most-used pattern of the week: Day 2 builds a list of verdicts this way, and the final project builds the list of rows your coders disagreed about.

🧪 Step 6 — count with a dict

The key is the label, the value is how many you have seen:

counts = {}                        # an empty dict: label -> how many
for item in items:
    label = item["label"]
    counts[label] = counts.get(label, 0) + 1   # count so far (0 if new), plus one

print(counts)                      # {'A1': 1, 'B1': 1, 'C1': 1}
  • counts[label] = ... — the same brackets you used to read a dict, now on the left of the =.
  • .get(label, 0) — reads the count so far, answering 0 when the label is new.

🧪 Step 7 — elif and and

elif adds branches: checked top to bottom, first match wins, exactly one runs.

for item in items:
    label = item["label"]
    if label == "A1" or label == "A2":     # `or` = either side is enough
        band = "basic"
    elif label == "B1" or label == "B2":   # only checked if the first did not match
        band = "independent"
    else:                                  # anything left over
        band = "proficient"
    print(label, "→", band)

🧪 Step 7 — and, on two coders

A row counts as a disagreement only when both coders labelled it and the labels differ:

for row in rows:
    a = row["CoderA"]
    b = row["CoderB"]
    if a != "" and b != "" and a != b:   # both labelled it, AND they differ
        print(row["id"], "disagreement:", a, "vs", b)
    else:
        print(row["id"], "no disagreement")

A blank cell is not a disagreement — one coder simply hasn’t got there yet. That is a decision about your data, and on Day 2 you make it yourself.

🧪 Step 8 — divide, and guard

Counting leads to dividing: how many right, out of how many there were?

right = 9
wrong = 3
print(round(right / (right + wrong), 3))   # 0.75

If both counts are 0 there is nothing to divide by, and Python stops with ZeroDivisionError:

if right + wrong == 0:      # nothing was scored at all
    score = 0.0             # no credit — and no division by zero
else:
    score = right / (right + wrong)

Every score you write on Day 2 has this shape.

🧪 Step 9 — wrap it in a function

You have written the same three steps twice. Name it once:

def ask(sentence):                     # `def` names a block of steps
    """Ask the model for the CEFR level of one sentence; return its reply."""
    prompt = f"What CEFR level (A1-C2) is this sentence? Answer with just the level. {sentence}"
    return ai.generate_text(prompt).strip()   # `return` hands the answer back

print(ask("The cat sat on the mat."))  # one line now does all three steps

print puts a value on the screen and it is gone; return hands it back, so you can store it, count it, or score it.

Steps 5 and 9 together

Because ask hands its answer back, it goes straight into the loop from step 5:

replies = []
for sentence in examples:          # the three sentences from step 3
    replies.append(ask(sentence))  # call the function, keep what it returns

print(replies)

A list of sentences in, a list of the model’s labels out. That is the shape of Days 3 and 4 — and the result goes back into the record from Session 2, {"id", "text", "label"}, only now label comes from ask(...) instead of being typed by hand.

Optional · What a model stores about a word

If there is time

Nothing later in the week depends on this section. It is here because it makes the Session 1 slides runnable — you can look at the numbers a model keeps for each word, and see where they stop working.

The notebook has it at the very end, with its own download cell.

One word, three hundred numbers

In Session 1 you saw that a model turns each word into a long list of numbers. You can look at that list.

word = nlp_vec("suggest")[0]      # read one word; [0] takes the first token
print("how many numbers:", word.vector.shape)
print("the first eight: ", word.vector[:8])
how many numbers: (300,)
the first eight:  [-0.126 -0.11  -0.61   0.105 -0.272  0.302 -0.014 -0.121]

Three numbers placed a colour in the Session 1 colour cube. It takes three hundred to place a word.

Why this matters

Session 1 claimed that words with similar meanings end up with similar numbers. That claim is checkable, and you are about to check it.

It matters because the same claim has a limit, and the limit is the reason attention exists. Every category you annotate this week — a CEFR level, a rhetorical move, a hedged claim — depends on context. Finding where these vectors stop is what makes the rest of the week necessary.

🧪 Let’s try — how close are two words?

.similarity(...) compares two vectors: the higher the number, the closer the words sit.

print("suggest / indicate:", nlp_vec("suggest").similarity(nlp_vec("indicate")))
print("suggest / banana:  ", nlp_vec("suggest").similarity(nlp_vec("banana")))
suggest / indicate: 0.672
suggest / banana:   0.168

✏️ Your turn — swap in two words from your own research area.

🧪 Let’s try — a word’s neighbours

Rather than guessing pairs, ask which words sit closest:

for neighbour in nearest("perhaps"):   # ✏️ your word here
    print(neighbour)
('possibly', 0.859)    ('might', 0.82)
('probably', 0.839)    ('rather', 0.817)
('certainly', 0.827)   ('though', 0.816)
('although', 0.825)    ('even', 0.812)
('however', 0.822)     ('maybe', 0.8)

Nothing told the model these words hedge a claim. They sit together because they turn up in the same positions in text.

Now try nearest("corpus")

('habeas', 0.59)     ('textual', 0.534)
('christi', 0.572)   ('writ', 0.485)
('corpora', 0.566)   ('habeus', 0.465)

The legal sense, the religious sense and the linguistic sense are collected into one vector, because there is only one vector available for the spelling.

nearest("hedge") does the same with garden hedges and financial hedging.

🧪 Let’s try — where these vectors stop

Session 1 used free in two sentences that mean different things:

banking = nlp_vec("your account is free of charge")
promo   = nlp_vec("claim your free prize now")

print("similarity:", banking[3].similarity(promo[2]))
similarity: 1.0

Not merely close — the same vector. One vector per word form, looked up the same way every time. That is what static means.

…and word order is gone too

A sentence’s vector is the average of its words, and an average does not record their order:

print(nlp_vec("the dog chased the cat").similarity(nlp_vec("the cat chased the dog")))
1.0

Two sentences with opposite meanings, one score.

Important

This is the gap Session 1 said attention closes. A model built on these vectors alone cannot represent context; the model behind ai.generate_text(...) can.

A map of the space

map_words([...]) flattens 300 numbers onto a page, keeping close vectors close.

map_words(["perhaps", "possibly", "maybe", "likely", "presumably",
           "suggest", "indicate", "demonstrate", "argue", "conclude",
           "cat", "dog", "horse", "rabbit", "sheep"])   # ✏️ your words

The animals land well away from the rest. The hedges and the research verbs do not split into two groups — they are all academic prose words, appearing in similar places in similar texts, and that is the only thing these vectors record.

The map shows what the model separates, which is not always what you want it to separate.
