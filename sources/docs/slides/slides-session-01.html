1 · Why this course

LLMs are everywhere now

Large language models are now common tools — for writing, translating, coding, searching.

So the question isn’t whether linguists will use them. It’s how to use them responsibly for linguistic analysis.

Linguistic annotation: promising but costly

One especially promising use is annotation — labelling language data for analysis.

  • But careful annotation is expensive: expert time, training, guidelines, double-coding.
  • If an LLM could annotate reliably, then it facilitates research.

The tempting question: can an LLM just do it for us?

Adequacy must be evaluated, not assumed

Here’s the seed of the whole course:

An LLM’s output is only useful if it’s adequate — and adequacy has to be evaluated, not assumed.

By Friday you will have critically evaluated an LLM on your own annotation task

4 · What is an LLM — and why it’s relevant

The plan — follow one example

An LLM is a kind of statistical machine-learning model.

To see its significance, we need to take a detour:

  1. Machine learning — what “learning from data” means
  2. NLP — machine learning applied to language
  3. How NLP researchers try to encode meaning
  4. Transformers architecture and its application to LLM

Statistical machine-learning model

Statistical Machine learning = a model learns patterns from data instead of being hand-coded with rules.

  • Rule-based ML: a human writes the rules.
  • Statistical ML: the model infers the rules from examples.

An ML model learns a probabilistic representation from statistical regularity in the data — which patterns tend to go with which outcome.

Example — spam detection

The classic ML task: given an email, decide spam / not-spam.

  • Rule-based: block anything containing FREE, WINNER, $$$ → brittle; spammers just write “F R E E”, and you block real mail.

  • ML: show the model thousands of emails already labelled spam / not-spam. It learns on its own which words (and combinations) predict spam.

The rules are inferred from examples, not written by hand.

What is the predictor in the ML model?

The idea of ML is like creating a smart regression model.

But then we need predictors (input features) to make predictons.

Three different classes of technologies.

  • One-hot text vector
  • Static Embeddings
  • Contextual Embeddings

The limit of Static embeddings

Meaning of a word depends on order and context:

  • “your account is free of charge” ✅ not spam
  • “claim your FREE prize now” 🚫 spam

Same word, opposite signal. This is because:

  • Many words are polysemous or homographic
  • Isolated word does not adds up to the meaning of the whole
    • idioms such as kick the bucket

Transformer architecture

  • Attention: every word decides which other words are relevant to it
  • Output: context-sensitive representations of each word and a document

Take the two frees from the last slide:

Sentence free attends most to Resulting sense
“your account is free of charge” account, charge banking, benign
“claim your FREE prize now” claim, prize, now promotional

Same string, two different vectors — because the neighbours differ. Static embeddings could not do this; there was only ever one vector for free.

Why this matters for you

This is the whole reason an LLM can annotate at all.

The categories you care about — is this stance hedged?, is this move a Gap or a Purpose?, what CEFR level is this? — are not properties of the words in isolation. They are properties of words in context.

A bag-of-words model cannot represent that. A transformer can.

Warning

“Can represent it” is not “gets it right.” That gap is what the rest of the week measures.

How LLMs are trained

An LLM is trained by self-supervised pretraining on huge amounts of text:

  • The task: predict the next word, over and over, on billions of sentences.
  • No hand-labelling needed — the text is its own answer key.

Producing natural language is just that same next-word prediction, run forward — which is why it sounds fluent.

Autoregressive model = the LLM

Predicts the token at time T given everything before it (T−1, T−2, …).

$ P(w_T w_1, w_2, , w_{T-1}) $

Run that forward, one token at a time → fluent, coherent text. That is exactly what a chat LLM does when it answers you.

The LLM re-absorbs the classic tasks

Historically, each task had its own model — POS tagger, NER model, parser, coreference model.

With scale + pretraining + prompting, one model can do many tasks.

Summary

An LLM is:

  • a statistical machine-learning model — it learns patterns from data,
  • of the autoregressive kind — it predicts the next token given the previous sequence,
  • built on the transformer architecture — attention lets it read context,
  • trained by next-word prediction on huge amounts of text.

6 · But — we need evaluation

The inversion

Classic NLP consumed annotation to build models.

Now the model can produce annotation. The arrow flips:

before: humans annotate → train the model now: the model annotates → and who checks it?

Trained to sound right, not be right

An LLM is optimized to produce fluent, plausible text.

Plausible is not the same as correct. So we check its labels against a human gold standard, using NLP’s own metrics:

  • inter-annotator agreement (percent + Cohen’s κ)
  • precision / recall / F1, confusion matrix

We’ll cover these on Day 2.

The punchline

Important

This course is the evaluation half of NLP, applied to LLMs.

NLP’s training half we mostly leave aside. Its evaluation half is exactly the rigor an LLM’s outputs need — and it’s what you’ll spend the week learning to run.
