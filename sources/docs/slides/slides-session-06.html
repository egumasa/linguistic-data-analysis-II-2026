Load the data first

Every evaluation begins by loading the two things it compares — the gold standard and the model’s predictions. This is a step of its own; the confusion matrix later is built from exactly what you load here.

gold = load_gold(GOLD_URL)                        # 72 records: {id, text, label}
predictions = load_predictions(PREDICTIONS_URL)   # one level per item, same order

Both are plain lists in the same order: predictions[i] is the model’s answer for gold[i].

Pass 1 · Step 1 — collapse to one yes/no question

Six levels → one question

CEFR has six levels. For pass 1 we ask one thing:

Is this sentence advanced — C1 or C2?

  • "yes" = C1 or C2 → this is our positive class
  • "no" = A1, A2, B1, B2

Note

Choosing the positive class is a decision, not a technicality. “Precision” and “recall” are always about the positive class. Change what counts as positive and every number changes. In your project, say out loud which class is positive before you report a score.

Build the twelve from what you loaded

The twelve rows are not typed in — they are sliced from the gold and predictions you just loaded (ids 17–28) and collapsed to yes/no. Same for, if, dictionaries as the rest of pass 1:

ADVANCED = ["C1", "C2"]          # the levels that count as "yes"

gold_12 = gold[16:28]            # positions 16–27 → ids 17–28
pred_12 = predictions[16:28]

items = []
i = 0
for g in gold_12:
    p = pred_12[i]               # the model's answer for that same sentence
    if g["label"] in ADVANCED:
        gold_answer = "yes"
    else:
        gold_answer = "no"
    if p in ADVANCED:
        pred_answer = "yes"
    else:
        pred_answer = "no"
    items.append({"id": g["id"], "text": g["text"],
                  "gold": gold_answer, "pred": pred_answer})
    i = i + 1

Ask it the first question

Is this item a true positive? That means both labels are "yes":

# `and` means BOTH sides have to be true:
if item["gold"] == "yes" and item["pred"] == "yes":
    print("TP")     # only runs when both are "yes"

Nothing printed. This is not a bug. Row 17 is not a TP, and one if can only answer one of the four questions.

Tip

An if with no else prints nothing when the condition is false. To classify every item we need all four questions, and exactly one of them must run.

Pass 1 · Step 3 — the four branches

The 2×2 table, written as if/elif

pred yes pred no
gold yes TP FN
gold no FP TN

Four cells, four branches, in the same order.

# checked top to bottom; only the FIRST match runs, so exactly one branch runs:
if item["gold"] == "yes" and item["pred"] == "yes":
    print("TP")      # advanced, and the model said advanced
elif item["gold"] == "no" and item["pred"] == "yes":
    print("FP")      # not advanced, but the model said advanced
elif item["gold"] == "yes" and item["pred"] == "no":
    print("FN")      # advanced, but the model said not advanced
else:
    print("TN")      # not advanced, and the model said not advanced

elif = “only if none of the above matched.” The branches are checked top to bottom and exactly one runs — so every item lands in exactly one cell. The final else needs no condition: if it isn’t TP, FP or FN, it can only be TN.

Pass 1 · Step 4 — make it a function

Twelve items, one rule

You are about to ask that same question of all 12 rows. Instead of copying the four branches twelve times, give them a name once:

def outcome(gold_label, pred_label):
    """Which of the four cells does this one item belong to?"""
    if gold_label == "yes" and pred_label == "yes":
        return "TP"      # `return` gives the answer back, instead of printing it
    elif gold_label == "no" and pred_label == "yes":
        return "FP"
    elif gold_label == "yes" and pred_label == "no":
        return "FN"
    else:
        return "TN"

Two changes from step 3, and only two: it is wrapped in def, and every print became a return.

print displays · return gives the value back

print(outcome("yes", "no"))     # gold said advanced, model said not advanced
FN
  • print — displays a value on the screen; the value is not kept.
  • return — gives the value back to the code that called the function, so you can store it and count it. Step 5 needs this.

Tip

Test it by hand before you use it. outcome("yes", "no") — gold says advanced, model said not advanced → FN ✓. Try all four combinations against the table. Do not use a function you have not tested.

Pass 1 · Step 5 — loop, and store every decision

One outcome per sentence

Now run that function over all 12 rows and keep the answers — the same “build a list in a loop” pattern you wrote on Day 1:

decisions = []                     # start empty; the loop adds to it
for item in items:                 # one pass per row of the table
    decisions.append(outcome(item["gold"], item["pred"]))   # add its outcome

print(decisions)                   # 12 outcomes, in the table's order
['TN', 'TP', 'TN', 'TN', 'TP', 'FN', 'TN', 'FN', 'TN', 'TN', 'TP', 'FP']

Twelve items in, twelve outcomes out — in the same order as the table. Position 6 is 'FN': row 22, the racing-bicycle sentence the model labelled not advanced.

Why store them, rather than just count?

We could have counted as we went. We keep the list because the list records every individual decision.

  • A metric is a summary. decisions is what is being summarised, and you can always return to it.
  • Each 'FN' and 'FP' points to a specific sentence you can read and discuss.
  • That is error analysis — the source of your research questions: is this the model’s error, or a problem in my scheme?

Note

Later today show_errors() does exactly this for you on the 6-class task — it selects the items the model got wrong and prints them. You have just written the same logic yourself.

Count the four outcomes

Tip

Pass 1 · Step 8 — precision, recall, F1

Precision — of what it called advanced, how much was correct?

Numbers first, so you can check it on paper:

print(3 / (3 + 1))            # TP / (TP + FP)
0.75

Same thing, read off the tally — so it survives a change of data:

print(tally["TP"] / (tally["TP"] + tally["FP"]))    # the same, from the tally
0.75

Of the 4 sentences the model called advanced, 3 really were. Precision = 0.75.

Precision — now as a function

def precision(tally):
    """Of everything CALLED advanced, how much really was?  TP / (TP + FP)"""
    tp = tally.get("TP", 0)      # .get(..., 0) so a missing count reads as 0
    fp = tally.get("FP", 0)
    if tp + fp == 0:             # the model never said "yes" at all
        return 0.0               # no correct positives, and no division by zero
    return tp / (tp + fp)        # correct positives, over all positive predictions

print(round(precision(tally), 3))   # round to 3 decimal places
0.75

Always guard the denominator

If a model never predicts the positive class, TP + FP is 0 and Python raises ZeroDivisionError. Returning 0.0 records that there were no correct positive predictions. Every metric you write today needs this guard.

Recall — your turn

Recall asks the other question: of everything that truly was advanced, how much did we identify?

\[R = \frac{TP}{TP + FN}\]

def recall(tally):
    """Of everything that TRULY was advanced, how much did we identify?"""
    tp = tally.get("TP", 0)
    fn = tally.get("FN", 0)       # ← the only real change
    if tp + fn == 0:              # nothing was truly advanced, so there is nothing to find
        return 0.0
    return tp / (tp + fn)         # correct positives, over all true positives in the gold

print(round(recall(tally), 3))
0.6

Three of the five genuinely advanced sentences were found. Recall = 0.60.

F1 — precision and recall in one number

Precision and recall move in opposite directions: if the model labels everything positive, recall becomes 1.0 and precision becomes very low. F1 is the harmonic mean, so a high value on one side cannot compensate for a low value on the other:

\[F_1 = 2 \cdot \frac{P \cdot R}{P + R}\]

def f1(tally):
    """Harmonic mean of precision and recall."""
    p = precision(tally)         # reuse the function you just wrote
    r = recall(tally)            # ...and the other one
    if p + r == 0:               # both zero — nothing to average
        return 0.0
    return 2 * p * r / (p + r)   # harmonic mean: a low value on either side lowers it

print(round(precision(tally), 3), round(recall(tally), 3), round(f1(tally), 3))
0.75 0.6 0.667

What 0.75 vs. 0.60 actually says

The gap between precision and recall describes how the model behaves:

  • Precision 0.75 > Recall 0.60 — the model applies the label advanced less often than the gold data does. When it does apply it, it is usually correct, but it labels some real C1 sentences as B2.
  • Both errors were C1 → B2 (rows 22, 24) — one level away, not far away.

Which error matters more in your project?

That is a research design question, not a statistics one.

  • Selecting texts for a C1 reading list — an FN (an advanced sentence you do not find) is more serious; favour recall.
  • Claiming in a paper which sentences are advanced — an FP (a sentence wrongly called advanced) is more serious; favour precision.

Say which one your project cares about before you report a score.

Pass 1 · Step 9 — Cohen’s κ

Why accuracy isn’t enough

Start with the easy number — observed agreement, the diagonal over the total:

n = tally["TP"] + tally["FP"] + tally["FN"] + tally["TN"]   # all 12 items
p_o = (tally["TP"] + tally["TN"]) / n   # the diagonal (both agreed), over the total
print(round(p_o, 3))
0.75

Gold and model agree on 9 of 12 items. That looks acceptable — but a model that answered “no” to every item would score 7/12 without using any information at all. Raw agreement gives a high score to a model that simply predicts the most frequent label.

Agreement expected by chance

\(p_e\) = the agreement two raters would reach by chance, given how often each one uses each label. Multiply their rates, label by label — the row and column totals from step 7:

# each line: how often GOLD says it × how often the MODEL says it = chance agreement
p_yes = ((tally["TP"] + tally["FN"]) / n) * ((tally["TP"] + tally["FP"]) / n)
p_no  = ((tally["FP"] + tally["TN"]) / n) * ((tally["FN"] + tally["TN"]) / n)
p_e   = p_yes + p_no          # chance agreement on "yes" plus chance agreement on "no"
print(round(p_yes, 3), round(p_no, 3), round(p_e, 3))
0.139 0.389 0.528
  • p_yes: gold says yes 5/12 × model says yes 4/12 = 0.139
  • p_no: gold says no 7/12 × model says no 8/12 = 0.389
  • More than half the agreement we observed (0.75) is expected by chance alone.

κ — agreement corrected for chance

\[\kappa = \frac{p_o - p_e}{1 - p_e}\]

Of the agreement that chance does not explain, how much did they achieve?

# observed minus chance agreement (p_o - p_e), over the agreement still available (1 - p_e):
print(round((p_o - p_e) / (1 - p_e), 3))
0.471
Cohen’s κ Landis & Koch McHugh
0.21–0.40 Fair Minimal
0.41–0.60 Moderate Weak
0.61–0.80 Substantial Moderate

75% agreement → κ = 0.47.

The same gap S4 showed you (80% → κ ≈ 0.52), now computed by your own code.

The whole calculation as one function

def kappa(tally):
    """Agreement corrected for chance: (p_o - p_e) / (1 - p_e)."""
    n = tally["TP"] + tally["FP"] + tally["FN"] + tally["TN"]   # every item
    p_o = (tally["TP"] + tally["TN"]) / n     # agreement we actually observed
    p_yes = ((tally["TP"] + tally["FN"]) / n) * ((tally["TP"] + tally["FP"]) / n)
    p_no = ((tally["FP"] + tally["TN"]) / n) * ((tally["FN"] + tally["TN"]) / n)
    p_e = p_yes + p_no                        # agreement expected by chance
    if 1 - p_e == 0:                          # chance already explains all agreement
        return 0.0
    return (p_o - p_e) / (1 - p_e)            # the share of the remaining agreement achieved

This is yesterday’s function

Nothing in kappa() knows whether column two came from your partner or a model. That is why S5’s agreement number and today’s evaluation number are the same statistic: κ measures two label columns, whoever produced them.

Pass 2 · The real task, with scikit-learn

Six levels, thirty-six cells

Drop the yes/no simplification. The actual task is the full ordinal CEFR scale: A1 · A2 · B1 · B2 · C1 · C2. Nothing new is loaded — the gold and predictions from the start already carry the full level; pass 1 only collapsed them to yes/no.

  • 4 cells → 36. Counting by hand is no longer practical.
  • One positive class at a time — with six classes you get six precisions, six recalls, six F1s.
  • The method is unchanged — to score C1, treat C1 as “yes” and all five others as “no”: pass 1, run six times. This is called one-vs-rest, and it is what classification_report does.
# ordered=True: the six levels form a scale, so also report weighted κ
evaluate(gold, predictions, ordered=True)

Accuracy is 39% — now look at how it is wrong

Before concluding that the model is useless, look at the size of its errors.

  • 97% of its answers are within one level of the gold label.
  • Only two sentences in the whole set are two levels away. No answer is further than that.
  • A model that had not learned the task would predict C2 for A1 sentences. This one does not.

Important

“Right idea, imprecise thresholds” is a completely different failure from “doesn’t understand the task” — and no single accuracy number can tell them apart. That is what the confusion matrix is for.

Rows are gold, so rows tell you what happened to each true level. But read down the columns — how often the model says each level. The gold set is balanced, 12 per level, so an unbiased rater would use each label about 12 times.

Central-tendency bias

The model said A2 twenty times and A1 four times. It said C2 exactly once — in 72 chances.

  • Predictions concentrate in the middle of the scale; the two ends are used rarely.
  • Why? When a rater — human or machine — has to judge something as unclear as “difficulty”, the middle categories are the safest choice.
  • Same finding as pass 1 — with “advanced” as positive, precision ran ahead of recall (0.75 vs 0.60 on your twelve). The model under-uses the top of the scale.

Tip

You will meet this tendency in your own annotation — and in your teammates’. It is one of the first things to check in a scheme that isn’t reaching acceptable κ.

Two κ values, same data

evaluate(..., ordered=True) printed both, right under the report:

Cohen's kappa            0.267
Cohen's kappa (weighted) 0.849   <- labels are ordered

Plain κ = 0.27 (“fair” / “minimal”) — because plain κ treats A1 → A2 as exactly as wrong as A1 → C2.

Quadratic-weighted κ = 0.85 — because CEFR levels are ordinal, so an error of one level should count less than an error of five:

\[w_{ij} = \frac{(i-j)^2}{(N-1)^2}\]

Report the one that matches your labels

Same predictions, 0.27 or 0.85 depending on a single argument. Ordered labels → weighted κ. Unordered categories → plain κ. State which you used and why; a κ reported without that sentence cannot be interpreted. (Arase et al. reported weighted κ = .628 on this task.)

Error analysis — the model’s error, or the scheme’s?

errors = show_errors(gold, predictions)   # a table of every item it got wrong
errors.head(15)     # ...or errors[errors["gold"] == "C2"] for the highest level

44 errors — too many to read one by one, and you do not need to. Read about a dozen, then look closely at the rows where gold is C2 or A1: disagreements concentrate at the two ends of the scale.

For each error you read, ask:

  1. Is the gold defensible here, or is this genuinely borderline?
  2. Would you and your partner have agreed on this sentence?
  3. Would a better-written scheme have prevented this error?

Note

Remember rows 19, 23 and 25 — the three obituary sentences. In pass 1’s yes/no task the model got all three right. In six classes it labelled every one of them A2 instead of A1. The question you ask determines which errors you can see.
